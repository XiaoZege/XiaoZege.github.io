> 这份计划按周排到大四秋招，起点是大二上（2026.10）。目前处于第 0 周，基建已完成，可直接从第 1 周开始。

你最大的资产是时间，最大的风险是“用两年把清单过一遍”。第一学期只做三件事：工具链跑通、一个能公网访问的项目、GitHub 与博客建起来。真正的分水岭是大二升大三那个暑假的第一段实习——它比多做一个项目重要得多。

**起点**：大二上 · 2026 年 10 月 **目标**：2029 届秋招（2028 年 9 月） **每周投入**：工作日 1.5–2h + 周末 4–5h

## 00 怎么用这份计划

这份计划按“周”写，但不要按“周”焦虑。它有三个使用规则，比具体内容更重要。

规则一：每周必须有产出

产出不是“学完了”，而是“多了一个 commit、一个能跑的功能、或一篇博客”。没有产出的学习周，等于没发生。

规则二：每 4 周一个检查点

检查点只问三个问题：能不能演示？能不能讲清一个技术决策？博客有没有更新？三个都否，就停下来补，不要往前赶。

规则三：落后就砍，不硬扛

进度落后 30% 时按固定顺序砍内容（见第 15 节），而不是熬夜补。熬夜补出来的进度，两周后一定还回去。

### 每周时间模板（12–14 小时）

**一周怎么分配（可按课表调整，但比例不要变）**

| 时间 | 时长 | 做什么 |
| --- | --- | --- |
| 周一 / 周三 / 周五 | 各 1.5 h | 40 分钟读文档或看概念，50 分钟写代码（当天必须有 commit） |
| 周二 / 周四 | 各 1 h | 补前一天的坑、写测试、整理笔记（不引入新知识） |
| 周六 | 4 h | 整块做项目：只做一件事，做到能演示 |
| 周日 | 1.5 h | 复盘 30 分钟 + 写周记 20 分钟 + 博客 40 分钟（双周一篇） |

考试月（每学期最后 3 周）把自学降到 30%，优先保 GPA。这不是妥协，是策略——生信专业课本身就是你的差异化。

32 个月分五个阶段。注意每个阶段的“关键产出”只有一个，不要同时追两个目标。

RAG 做深（评测与调优）→ 异步与 Redis → 算法启动 → Agent 基础与 LangGraph → 第二个主项目。

产出：offer 或 考研上岸

## 02 第 0 周：基建（10/26–11/01）

这一周不要学任何“知识点”，只装工具、建账号、发第一篇东西。做完这周，你就已经超过 80% 说“我要开始学”的人。

### 2.1 装环境

PowerShell

```powershell
winget install --id Python.Python.3.12 -e
winget install --id astral-sh.uv -e
winget install --id Git.Git -e
winget install --id Microsoft.VisualStudioCode -e
winget install --id Hugo.Hugo.Extended -e

python --version
uv --version
git --version
hugo version
```

VS Code 装四个扩展：Python、Ruff、Even Better TOML、GitLens。装完重启终端，确认命令都能跑。

### 2.2 配 Git 与 SSH

PowerShell

```powershell
git config --global user.name "你的真名拼音"
git config --global user.email "你的邮箱"
git config --global init.defaultBranch main

ssh-keygen -t ed25519 -C "你的邮箱"
# 连续回车，不设密码短语
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

复制输出的整行内容 → GitHub → Settings → SSH and GPG keys → New SSH key → 粘贴 → 保存。然后验证：

```powershell
ssh -T git@github.com
# 看到 "Hi 用户名! You've successfully authenticated" 就成功
```

### 2.3 建 GitHub 主页

新建仓库，仓库名必须**和用户名完全一致**，勾选 “Add a README file”。这个仓库的 README 会显示在你的主页最上方。内容模板见第 9 节。

### 2.4 建博客

用 Hugo + GitHub Pages，完全免费、可绑域名、简历上能直接放链接。完整步骤见第 10 节，这一周只要做到“本地能预览”即可，部署可以放到周末。

### 2.5 建笔记与周记

新建仓库 `learning-log`，里面放 `2026/` 目录，每周一个 Markdown 文件。周记模板见第 12 节。这个仓库是你两年后写简历时最值钱的东西——它证明你持续在做事。

### 2.6 自测：判断你的起点

下面 10 题，能独立写出 6 题以上，可以直接从第 1 周开始；少于 4 题，先花 3 天补 Python 基础语法（变量、循环、函数、列表/字典、文件读写）。

- 读一个 CSV，按某列分组求和，输出结果

- 写一个函数，接收列表，返回去重后的结果（保持顺序）

- 用 `try/except` 处理文件不存在的情况

- 写一个类，有属性和方法，能打印出可读的对象信息

- 用列表推导式生成 1 到 100 的平方

- 用字典统计一段文本里每个词出现的次数

- 把两个列表合成一个字典

- 用 `with open()` 读文件并逐行处理

- 解释 `a = [1,2]` 与 `b = a` 后修改 `b` 会发生什么

- 用 `sorted()` 按字典的某个字段排序

检查点 1（W4 末）

仓库有 README、测试、CI、类型标注；博客 ≥ 3 篇；能向别人演示 file-tool。做不到就停一周补，不要进入 Web 阶段。

检查点 2（W8 末）

有一个别人能点开的公网 URL；能讲清“为什么这样分层”“索引加在哪一列”。这是你简历上的第一个项目。

检查点 3（W11 末）

RAG 能回答你自己准备的问题，且你知道它答错的 3 个原因。这个“知道哪里错”，就是后面做调优的起点。

考试月提醒

W10–W11 通常撞上期末。把这两周的任务减半：只做 RAG 最小版，评测和流式可以挪到寒假。GPA 掉下去的代价，比晚两周做项目大得多。

## 04 寒假：4 周把 RAG 做深

寒假是唯一一段没有课表干扰的时间，用来把“能跑的原型”变成“能写进简历的项目”。

**寒假四周（2027.01.18–02.21，春节周可休 3–5 天）**

| 周 | 主题 | 具体任务 |
| --- | --- | --- |
| 寒 W1 | 混合检索 | 加 BM25（关键词）+ 向量双路召回，融合排序；对比“只用向量”与“混合”在 20 条问题上的命中差异 |
| 寒 W2 | 评测体系 | 评测集扩到 50–100 条（问题 + 标准答案 + 应召回的文档）；写脚本自动算 Top-5 召回率、答案命中率、平均延迟 |
| 寒 W3 | 重排与调优 | 加 rerank 模型；做 4 组对比实验（chunk 大小 × top-k × 是否 rerank），把结果整理成表格 |
| 寒 W4 | 工程化收尾 | 权限过滤（按文档来源/部门）、结果缓存、流式输出；重写 README（截图 + 数据表 + 架构图）；写一篇长文 |

寒假结束时你手里应该有：一个带评测数据的 RAG 项目、一篇有实验表格的长文、一张能放进简历的指标表（召回率、延迟、成本）。

## 06 大二升大三暑假：第一段实习

这个暑假的唯一优先级是**拿到一段能写进简历的经历**，而不是再做一个项目。三种可行路径，按优先级排列：

1. 公司实习

AI 创业公司、本地软件公司、传统企业的数字化部门都可以，远程也行。渠道：BOSS 直聘、实习僧、牛客、学长学姐内推。此时你已有 2 个项目，足够投“日常实习”。

2. 学校实验室

找生信/计算生物方向的老师，说明你会 Python、会做数据处理与 Web 服务，愿意做“平台/工具”类工作。实验室经历可以产出论文署名或工程项目，对生信方向尤其有用。

3. 生信交叉项目

前两条都没成时的替代方案：做“文献/组学调研 Agent”，接 PubMed 检索、数据解析、报告生成、引用溯源。这是你区别于所有计算机专业候选人的东西。

并行任务：算法每天 2 题；开始计算机基础（操作系统 + 计算机网络，按“面试够用”的标准，不啃教材全书）。

## 09 小教程 A：GitHub 从 0 到“看起来像样”

### 9.1 账号怎么设置

- 用户名用**真名拼音**或“拼音 + dev”，不要用中二 ID——面试官会看。

- 头像用真实照片或简洁图形；Bio 一句话：`Bioinformatics student @ FAU · learning AI engineering`。

- 填 Location 和博客链接。一个空 profile 会让面试官直接关掉页面。

### 9.2 Profile README 模板

新建仓库，名字与用户名完全相同，勾选 Add README。内容控制在 20 行以内：

```powershell
### 你好，我是 XXX
福建农林大学 · 生物信息学 · 大二 | 正在学 AI 应用工程

**现在在做**
- 企业知识库问答：FastAPI + Chroma + bge-m3，Top-5 召回率 88%
- 每周一篇技术复盘 → https://你的用户名.github.io

**技术栈**
Python / FastAPI / MySQL / Redis / Docker / LangChain

**最近**
- [kb-qa](仓库链接)：文档上传 → 混合检索 → 带引用回答
- [llm-client](仓库链接)：带重试与限流的 LLM 客户端
```

### 9.3 一个仓库“看起来专业”的 7 件事

**仓库自检清单**

| 要素 | 标准 |
| --- | --- |
| README | 一句话定位 + 一张截图或 GIF + 快速开始（3 条命令）+ 技术栈 + 效果数据 + 已知限制 |
| LICENSE | MIT，一行搞定；没有 license 别人不敢用 |
| .gitignore | 排除 `__pycache__`、`.venv`、`.env`、数据文件 |
| CI | GitHub Actions 跑 ruff + pytest，README 顶部放 badge |
| Releases | 每个阶段打一个 tag（v0.1、v0.2），写一句变更说明 |
| Demo | 能点开的地址，或 30 秒录屏 |
| 提交历史 | 多次、有意义的 commit，不要一次 push 全部代码 |

### 9.4 commit 规范

用“类型: 做了什么”的格式，中英文都可以，但要统一：

```powershell
feat: 增加文档上传接口
fix: 修复中文切分导致的乱码
docs: 补充部署与回滚说明
refactor: 抽出向量库接口，支持切换 Chroma / PGVector
test: 补充 LLM 重试逻辑的单元测试
chore: 升级依赖并锁定版本
```

### 9.5 该发哪三类仓库

learning-log（持续型）

周记 + 实验记录 + 踩坑。它的价值不在代码，而在“连续 100 周的 commit 记录”，这是最便宜的可信度证明。

工具库（小而美）

`file-tool`、`llm-client` 这类 200–500 行的库。展示工程习惯：测试、类型、文档、发布。

主项目（能讲 20 分钟）

`kb-qa` 与 `agent-service`。要有评测数据、部署地址、架构图。这是简历的主角。

### 9.6 不要做的五件事

- 把课程作业原样上传，README 只写“这是我的作业”。

- 一次性 push 几千行代码，提交历史只有一条 “init”。

- fork 一堆仓库但从不改动——fork 数量不加分，merged PR 才加分。

- 把别人的项目改个名字当自己的（commit 历史会暴露）。

- 仓库里提交 `.env` 或 API Key（一旦泄漏，GitHub 会扫到并通知服务商）。

## 10 小教程 B：技术博客在哪里开、怎么写

### 10 .1 平台怎么选

**平台对比与建议**

| 平台 | 优点 | 缺点 | 定位 |
| --- | --- | --- | --- |
| GitHub Pages + Hugo | 完全可控、免费、可绑域名、简历可放链接 | 需要一点配置，本身没有流量 | 主站 |
| 掘金 | 中文技术社区流量最大，容易被搜到，有创作者等级 | 需要审核，编辑器一般 | 同步分发 |
| 知乎 | 长文与观点传播好，适合复盘类 | 技术检索弱 | 阶段性长文 |
| CSDN | SEO 强，百度收录快 | 广告多、社区口碑一般 | 可选同步 |
| 公众号 | 私域沉淀 | 不可被搜索、排版成本高 | 后期再说 |

结论：**主站用 GitHub Pages，文章同步一份到掘金**。主站证明“我有自己的东西”，掘金负责被搜到。

### 10 .2 Hugo + GitHub Pages 搭建步骤

PowerShell

```powershell
hugo new site blog
cd blog
git init
git submodule add https://github.com/adityatelange/hugo-PaperMod themes/PaperMod

# 新建文章
hugo new posts/hello.md

# 本地预览（含草稿）
hugo server -D
```

在 `hugo.toml`（或 `hugo.yaml`）里至少配置四项：

```powershell
baseURL = "https://你的用户名.github.io/"
title = "XXX 的技术笔记"
theme = "PaperMod"
languageCode = "zh-cn"
```

然后：GitHub 新建仓库 `你的用户名.github.io`（必须是这个名字）→ push → 仓库 Settings → Pages → Source 选 GitHub Actions → 添加官方 Hugo 部署 workflow。几分钟后访问 `https://你的用户名.github.io`。

想绑自定义域名（比如 `blog.xxx.com`），在仓库 Settings → Pages 填域名，并在域名服务商加一条 CNAME 记录。

### 10 .3 每篇文章的六段结构

1. 问题

一句话说清你要解决什么，以及为什么值得写（不是“今天学习了 XX”）。

2. 最初的做法

你一开始怎么想的、怎么写的、结果是什么。有代码就贴关键 10 行。

3. 卡点

报错、异常数据、性能现象。把错误信息原样贴出来，这是搜索流量的来源。

4. 怎么定位

你用了什么手段：日志、对比实验、最小复现、读源码。这一段最能体现能力。

5. 最终方案与数据

一张前后对比表（延迟、召回率、内存、成本），比任何形容词都有说服力。

6. 可复用结论

三条以内，写成“下次遇到 X，先检查 Y”。

标题公式：具体对象 + 数字变化。比如「三种切分策略对比：Top-5 召回率 61% → 88%」，不要写「RAG 学习笔记（一）」。

### 10 .4 前 10 篇选题（跟着学习进度写）

1. 大二如何搭一套不折腾的 Python 环境（uv + ruff + pytest）

1. 为什么脚本读 1G 文件会崩：生成器与惰性求值

1. 装饰器到底解决什么问题：从 LLM 重试说起

1. 给玩具项目加类型标注，我踩了哪些坑

1. 用 FastAPI 30 分钟写一个能用的 API

1. 一条查询从 2s 到 20ms：索引到底怎么加

1. FastAPI 分层：别把业务逻辑写在路由里

1. 把 FastAPI 部署到 2 核 2G 服务器

1. 我的第一个 RAG：三种切分策略对比

1. RAG 召回率从 61% 到 88%：我做了哪四件事

频率：**双周一篇**就够，关键是每篇都有实验或数据。一年 20 篇，比一周一篇的水文有用得多。

## 11 小教程 C：开源贡献怎么搞

开源贡献不是“给大项目写核心代码”，它有明确的四级台阶。从第一级开始，每一步都能写进简历。

### 11 .1 四级路径

**按难度递进的开源贡献路径**

| 层级 | 时间 | 做什么 | 去哪里找 |
| --- | --- | --- | --- |
| L1 文档 | 第 1–2 个月 | 错别字、失效链接、补一个示例、翻译一段文档 | 你正在用的库的 `docs/` 目录 |
| L2 新手 issue | 第 3–6 个月 | 带 `good first issue` 标签的小 bug 或小功能 | GitHub 搜索、up-for-grabs.net |
| L3 修自己的 bug | 第 6 个月起 | 你在项目里踩到的库 bug：最小复现 → 修 → 加测试 → PR | 你自己的报错日志 |
| L4 维护小库 | 大二下起 | 把自己反复写的工具抽成库，认真回 issue 和 PR | 自己的 GitHub |

### 11 .2 怎么找合适的 issue

在 GitHub 搜索框直接粘贴：

```powershell
label:"good first issue" language:Python stars:>1000 is:issue is:open
label:"documentation" language:Python is:issue is:open
```

挑选标准（三个都满足才动手）：有明确的复现步骤；维护者最近 30 天有回复；预期改动小于 50 行。不满足的 issue 会让你卡两周，然后放弃。

### 11 .3 一次完整 PR 的命令流程

```powershell
# 1. 在网页上 Fork 目标仓库，然后克隆自己的 fork
git clone git@github.com:你的用户名/目标仓库.git
cd 目标仓库

# 2. 加上游仓库，方便同步
git remote add upstream git@github.com:原作者/目标仓库.git

# 3. 开分支（不要直接在 main 上改）
git checkout -b fix/docs-typo

# 4. 改代码 / 改文档，然后本地验证
pytest
ruff check .

# 5. 提交
git add .
git commit -m "docs: fix broken link in quickstart"
git push origin fix/docs-typo
```

然后在网页上点 “Compare & pull request”，按仓库模板填写：问题是什么、怎么复现、改了什么、怎么验证。等 review，按意见改，同一个分支继续 push 即可。

### 11 .4 礼仪与被拒的原因

先读规则

动手前读 `CONTRIBUTING.md` 和 issue 模板。不读规则就提 PR，是最常见的被拒原因。

一个 PR 只做一件事

“顺手重构了一下”会让 review 无法进行。重构另开 PR。

先讨论再写代码

大改动先在 issue 里说“我打算这样改，可以吗”，避免写完被拒。

被拒很正常

维护者可能因为方向不符、已有计划而关闭。记录原因，换一个 issue，不要争论。

### 11 .5 它对求职的实际价值

一个 merged PR 证明的是“你能在别人的代码库里工作”——这是企业最看重、也最难从自学项目里看出来的能力。它比 10 个 star 的自娱项目更有说服力，但前提是**真的被合并**，而不是一堆挂着的 PR。

## 12 每周复盘与每月检查

### 12 .1 周记模板（5 行，10 分钟）

```powershell
## 20 27-W03（11/16–11/22）
- 做了什么：（一句话 + 链接/commit）

- 怎么解决的：（方法，没解决就写下一步）
```

存在 `learning-log/2027/W03.md`。周记不要写成日记，只保留可复用的信息。

### 12 .2 每月检查（15 分钟）

- 本月有 ≥ 4 次有意义的 commit

- 本月有 ≥ 2 篇博客（或 1 篇有实验数据的）

- 本月有一个能演示的新功能

- 我能讲清本月学到的一个技术决策（为什么这么选）

- GPA 没有因为自学而明显下滑

## 13 和课程、GPA 怎么平衡

专业课优先

生物信息、统计、Linux、分子生物学——这些是你和计算机专业候选人拉开差距的地方，也是考研复试的内容。不要为了写代码而翘课。

把作业升级成项目

课程里的序列分析脚本、数据统计作业，加一个 CLI、加测试、写 README，就是 GitHub 项目。同样的时间，产出两份成果。

考试月降速

每学期最后 3 周，自学时间降到 30%。项目停在下个能跑的状态，不要留半成品。

英语是硬需求

每天 20 分钟读英文文档或 GitHub issue。这不是“额外学习”，是主线的一部分——官方文档永远比二手教程准确。

## 14 分叉点：考研还是就业

大三上末必须做决定，但不用现在纠结——两条路在大二、大三的准备有 80% 重合（项目、代码、英语、生信基础）。判断标准：

**选择依据**

| 如果你的目标是 | 建议 | 理由 |
| --- | --- | --- |
| 生信 AI 算法、大厂算法岗 | 考研（生信 / 计算生物 / 计算机） | 这类岗位普遍要求硕士，本科简历阶段就会被卡 |
| AI 应用开发、AI 工程落地 | 就业（本科 + 实习可行） | 考的是工程能力与项目深度，学历可以用经历对冲 |
| 还不确定 | 先按就业准备，大三上再评估 | 就业准备（项目、实习）对考研复试同样有用，反过来不成立 |

一个现实提醒

保研需要大一到大三的成绩排名，双非院校名额很少。如果你现在成绩在专业前列，值得认真评估保研；如果不在，就不要为了“可能保研”而放弃实习——两条路的投入方式不同。

## 15 落后了怎么办：固定取舍顺序

落后是常态。按这个顺序砍，从最先砍到最后砍，不要凭感觉：

**进度落后 30% 时的砍内容顺序**

| 顺序 | 砍什么 | 影响 |
| --- | --- | --- |
| 1 | K8s、分库分表、复杂中间件 | 几乎无影响（初级岗不问） |
| 2 | Java 相关内容 | 无影响（AI 应用岗不问） |
| 3 | 视频/IM 类业务项目 | 无影响，甚至减分 |
| 4 | 算法题量（从 200 降到 100） | 影响笔试通过率，但不致命 |
| 5 | 博客频率（双周改月更） | 影响曝光，不影响能力 |
| 最后 | RAG / Agent 项目深度 | **不能砍**——这是你唯一的差异化 |

最不该做的两件事

一是同时开两个新项目（都做不完）；二是为了追进度跳过评测与测试（项目看起来完成了，但面试一问就露）。宁可少一个功能，也要保留数据和测试。

## 16 资源清单

**按优先级排列，不要贪多**

| 类别 | 资源 | 怎么用 |
| --- | --- | --- |
| 文档（首选） | Python 官方文档、FastAPI、pytest、ruff、SQLAlchemy、LangChain / LangGraph、Docker | 遇到问题先查官方文档，其次搜索，最后问 AI |
